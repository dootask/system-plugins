# 29.9.0

## 引擎

- Manticore Search 升级到 29.9.0。已有的 28.4.4 数据直接沿用：不清库、不重新生成向量、不需要全量重建。
- 修复服务器非正常重启/停机后引擎反复崩溃重启、「搜索状态」面板显示「表缺失」的问题。原因：binlog 元数据登记了磁盘上已不存在的日志文件，引擎每次启动都 FATAL 退出，而表数据本身是完好的。现在引擎会跳过缺失的 binlog 文件（`--replay-flags=ignore-open-errors`）并继续回放其余日志，尚未落盘的写入不会丢。
- 兜底：若上一次启动仍因 binlog 损坏失败，启动脚本会把 binlog 目录改名备份为 `binlog.corrupt-<时间>`（保留最近 3 份）后重新启动。仅存在于该 binlog 里的写入会被丢弃，由主程序按源数据重新同步。
- 引擎关停宽限期延长到 120 秒，大索引有时间落盘，不再被 Docker 默认 10 秒后强杀。
- 容器健康检查改为不做 TLS 协商。升级后首个引擎容器上，MySQL 端口曾声明支持 SSL 却握手失败（报 `SSL connection error`），使正常工作的引擎显示 unhealthy；重装后未再复现，原因未查明；明文连接和 unix socket 始终不受影响。

## 搜索状态面板

- 覆盖率表现在能区分原因：「引擎离线」「表未加载」（引擎在线但表无法服务）「表缺失」（表确实不存在），不再把所有故障都显示成「表缺失」。
- 表未加载时，管理员菜单同样会推红点告警。

## 说明

- 升级仅验证了 28.4.4 → 29.9.0；数据被 29.x 打开后，不支持降级回旧引擎。
